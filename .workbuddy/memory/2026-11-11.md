## Android 15 edge-to-edge 顶部安全区适配（用户反馈：状态栏挡住首页标题）
- 原因：Capacitor 8 在 Android 15 上强制 edge-to-edge，WebView 铺满全屏；项目只有底部用了 `env(safe-area-inset-bottom)`，顶部完全没让位。
- 做法：`:root` 里统一出 `--safe-top / --safe-right / --safe-bottom / --safe-left` 四个变量（值取 `env(..., 0px)`，浏览器里恒为 0，不影响网页版），所有顶部容器改用 `calc(原值 + var(--safe-top))`。
- 覆盖的容器：`.page`（首页/导入/调音器/错误页）、`.score-header`（含两处媒体查询覆写）、`.fasttune-page`（68px 和移动端 20px 两处）、`.home-page`（桌面 40px）、`.selected-chord-panel` 的 sticky `top`、`.img-viewer` 的 padding。
- **踩坑**：移动端媒体查询第 259 行 `.page { padding: 20px 16px 100px }` 把顶部写死，压掉了 `:root` 的变量。凡是被媒体查询重新声明 `padding` 简写的页面容器，都必须同步改成 calc，否则 safe-top 静默失效（第一次改完量出 logo 距顶仍只有 21px 才发现的）。
- 兜底：新增 `src/lib/safe-area.ts`，用探针元素实测 `env(safe-area-inset-top)`，若为 0 且 `Capacitor.isNativePlatform()` 为真，就按 24px（Android）/ 47px（iOS 刘海）补上，防个别 ROM 不返回 safe area。
- 验证方法：`npm run build` 后把 dist CSS 里 `--safe-top: env(...)` 临时 sed 成 `32px`，用 headless Chrome 按 412x915 截图，再用 PIL 量 logo 顶部像素位置（应为 52 左右）。三轮都通过：首页、导入页、调音器页。
- 顺手发现但未修：412 CSS 宽下调音器页右上角 Auto 文案被裁、导入页类型卡片右侧溢出，可另开一轮处理。

## 和弦库 Tab（下午，11:25 前后）
- 新增底部第 4 个 tab「和弦库」（路由 `/chords`，`ChordsPage.tsx`），bottom-nav 改 4 列，导入按钮从悬浮大圆改为 38px 实心 chip（`.import-chip`），桌面 rail 同步加了入口。
- 和弦数据重构：`src/data/chords.json`（107 个指法，带 group 字段）+ `src/data/chords.ts`（类型、分组元数据、resolveChord）。旧 `CHORDS`/`getChord` 保留兼容。
- **关键机制**：`resolveChord` 未命中时按「同性质 + 同低音关系」整体移调（横按、手指数一起平移），所以 Bbsus4 这类没单独收录的和弦也有能按的指法；`normalizeSuffix` 处理 M7/min/-7/ø/° 等写法，无法精确匹配时降级为近似指法（UI 打「简化指法」标签）。
- **校验**：`scripts/check-chords.mjs`（`npm run check:chords`）按标准调弦算每根弦实际音高，比对和弦组成音、检查根音在最低音（斜杠和弦放行低音）、横按区间内不能有更低品。第一轮抓出 86 个假阳性（横按检查逻辑写反了，手指按在横按上方是正常的），修正后 107 个全过。
- `ChordDiagram.tsx` 重写：viewBox 118×124，横按用 rect（单弦不画横按）、高把位左侧标「N品」、开放/闷音标记。画布曾因「N品」贴边从 110 加宽到 118。
- 和弦详情底部弹层 `ChordDetailSheet.tsx`（类名 `chord-detail-*`，避免和歌词谱 `.chord-sheet` 混淆）：大图、组成音 chips、逐弦说明、试听扫弦。`guitarTone.ts` 新增 `playChord`：用 playbackRate=2^(品/12) 把六弦采样送到对应品，间隔 52ms 顺扫，stopGuitarTone 会一并停掉和弦声部。
