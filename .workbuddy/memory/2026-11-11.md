## Android 15 edge-to-edge 顶部安全区适配（用户反馈：状态栏挡住首页标题）
- 原因：Capacitor 8 在 Android 15 上强制 edge-to-edge，WebView 铺满全屏；项目只有底部用了 `env(safe-area-inset-bottom)`，顶部完全没让位。
- 做法：`:root` 里统一出 `--safe-top / --safe-right / --safe-bottom / --safe-left` 四个变量（值取 `env(..., 0px)`，浏览器里恒为 0，不影响网页版），所有顶部容器改用 `calc(原值 + var(--safe-top))`。
- 覆盖的容器：`.page`（首页/导入/调音器/错误页）、`.score-header`（含两处媒体查询覆写）、`.fasttune-page`（68px 和移动端 20px 两处）、`.home-page`（桌面 40px）、`.selected-chord-panel` 的 sticky `top`、`.img-viewer` 的 padding。
- **踩坑**：移动端媒体查询第 259 行 `.page { padding: 20px 16px 100px }` 把顶部写死，压掉了 `:root` 的变量。凡是被媒体查询重新声明 `padding` 简写的页面容器，都必须同步改成 calc，否则 safe-top 静默失效（第一次改完量出 logo 距顶仍只有 21px 才发现的）。
- 兜底：新增 `src/lib/safe-area.ts`，用探针元素实测 `env(safe-area-inset-top)`，若为 0 且 `Capacitor.isNativePlatform()` 为真，就按 24px（Android）/ 47px（iOS 刘海）补上，防个别 ROM 不返回 safe area。
- 验证方法：`npm run build` 后把 dist CSS 里 `--safe-top: env(...)` 临时 sed 成 `32px`，用 headless Chrome 按 412x915 截图，再用 PIL 量 logo 顶部像素位置（应为 52 左右）。三轮都通过：首页、导入页、调音器页。
- 顺手发现但未修：412 CSS 宽下调音器页右上角 Auto 文案被裁、导入页类型卡片右侧溢出，可另开一轮处理。

## 弹唱谱图片和弦识别（下午，OCR 接入）
- 方案：tesseract.js v7 纯前端 OCR，worker/wasm/训练数据全部本地打包，不依赖 CDN（国内网络考虑）。
  - `public/vendor/tesseract/`（worker.min.js + tesseract-core-simd-lstm.wasm.js，构建时由 `scripts/copy-ocr-assets.mjs` 从 node_modules 复制，已 gitignore）；`public/tessdata/eng.traineddata.gz`（best_int 量化模型 2.9MB，直接提交）。
  - **corePath 传单个 .wasm.js 文件路径可跳过 tesseract.js 的 SIMD 变体检测**（worker 源码里判断结尾是 "js" 就直接 importScripts）。
  - 只跑英文 LSTM（oem=1）：和弦是拉丁字母，中文歌词变噪声，正好配合 chordParse 的「和弦行」过滤。
- **关键技术发现**：和弦记号字号小（20~40px），直接 OCR 会把粗体字母切成两个字符（C→Cc、F→FIF），**识别前先把图片放大到约 1600px 宽**（上限 2 倍 / 12MP）后全部正确。DPI 参数影响不大，设 96。
- `src/lib/chordOcr.ts`：recognizeChords(blob) → 用词级 bbox 按纵向位置重组「视觉行」（和弦行浮在歌词上方，整页 OCR 常黏成一行）→ chordCoverage ≥ 0.6 判定和弦行 → 输出干净的和弦行文本存进 sourcePages[].text。cleanWord 处理开头重复字母伪影（Cc→C），但先 resolveChord 判断原词（保住 Bbmaj7 这类降号和弦）。
- 导入页（ImportPage）：type=chord 时图片加入即排队后台 OCR（队列直接带 Blob——enqueueOcr 与 setPages 同批执行时 pagesRef 还是旧数组，第一版在这里静默丢任务）；缩略图红色徽章显示进度；第 2 步顶部横幅汇总识别出的和弦数；保存时 text 写入 sourcePages。
- 谱面页（ScorePage）：原图模式下也渲染 UsedChordStrip——滚动模式钉在图上方（sticky），单页翻页模式放原图下方；摘要行新增「识别和弦」按钮，给旧谱子/没识别完的谱子补跑 OCR 并保存回 score。
- 验证脚本（node 直跑 tesseract.js v7 会因 wasm-feature-detect 语法报错，本机 Node 22.22 不支持 import.source，所以全部走浏览器）：
  - `scripts/test-ocr-browser.mjs`：CDP 直连 headless Chrome，在真实页面上下文跑 recognizeChords；
  - `scripts/test-import-flow.mjs`：全流程自动化（选类型→DataTransfer 注入图片→等徽章→填标题→保存→断言和弦条），dev 和 `vite preview` 生产构建都通过，识别出全部 11 个和弦；
  - fixture：`scripts/fixtures/chord-sheet.html`（Chrome 截图生成模拟弹唱谱，注意 chord 行超宽会被视口裁掉）。
- 已知取舍：OCR 偶发丢单个和弦词（置信度<40 被滤掉），不影响和弦集合完整性；歌词行乱码（"HE AR ARE"）永远不会被误判为和弦行。
